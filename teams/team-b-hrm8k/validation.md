# 검증 기록: lm-eval `hrm8k`와 문항 단위 비교

> 팀: 최재희야(B팀) · 설계 문서: [design.md](design.md) 6번의 lm-eval 비교 결과
>
> 업스트림 PR: [huggingface/lighteval#1513](https://github.com/huggingface/lighteval/pull/1513) (이슈 [#1479](https://github.com/huggingface/lighteval/issues/1479))
>
> 근거 자료: [hrm8k-lighteval-experiments `48e6b27`](https://github.com/dw021213/hrm8k-lighteval-experiments/tree/48e6b27c5e62aeb927de57251cd3e153f7c0ae54#full-runs-with-two-models-2026-11-17-2026-11-18)

## 1. 요약

- 두 모델로 8,011문항을 한 번씩 생성하고, 같은 응답을 lm-eval `hrm8k`와 Lighteval 태스크 지표로 각각 채점했다.
- 프롬프트는 8,011문항 모두 lm-eval과 같다.
- 판정이 다른 문항은 Qwen2.5-72B에서 138개, Llama-3.1-8B에서 455개다.
- Qwen2.5-72B의 138개는 모두 읽고 원인을 붙였다. 131개는 Lighteval의 채점이 옳고, 7개는 lm-eval의 채점이 옳다.
- Llama-3.1-8B의 455개 중 432개는 `\boxed{}`가 없는 답이다. 여기서 두 채점기의 대체 규칙이 갈린다.
- 대체 규칙(`\boxed{}`가 없으면 맨 오른쪽 숫자나 식)은 유지한다. 근거는 4번에 있다.

## 2. 실행 기록

| 항목 | Qwen2.5-72B | Llama-3.1-8B |
|---|---|---|
| 모델 (OpenRouter) | `qwen/qwen-2.5-72b-instruct` | `meta-llama/llama-3.1-8b-instruct` |
| provider | DeepInfra, fp8 양자화. 다른 provider로 넘어가지 않게 고정 | 같음 |
| 실행 날짜 (UTC) | 2026-11-17 | 2026-11-18 |
| 생성 설정 | temperature 0, `max_tokens` 2048, 0-shot, user 메시지 하나, 시스템 프롬프트 없음, stop 없음 | 같음 |
| 문항 | 전체 8,011문항, 실패 0 | 전체 8,011문항, 실패 0 (재시도 후 성공 100) |
| Lighteval | 팀 브랜치 `5d86619`, 데이터 리비전 `c360cab` | 같음 |
| lm-eval 채점기 | `314f717`의 `hrm8k` `process_results` | 같음 |
| 비용 | 2.16달러 | 0.41달러 |

실행은 정세엽이 했고, 분석은 김동우가 했다.

설계 6번의 세 단계 중 1단계(두 도구로 따로 생성해 생성 결과를 비교)는 하지 않았다. 생성을 OpenRouter API로 했는데, API는 temperature 0에서도 같은 요청에 다른 답을 낸다. 시험 실행 50문항을 본 실행과 비교하니 응답이 같은 문항이 18개뿐이었다. 두 도구로 따로 생성하면 생성 차이와 채점 차이가 섞인다. 생성은 한 번만 하고 2단계와 3단계를 했다.

## 4. `\boxed{}` 없는 답

설계 6번에서 실행마다 기록하기로 한 숫자다.

| 묶음 | Qwen2.5-72B: `\boxed{}` 없음 | 그중 잘림 | Llama-3.1-8B: `\boxed{}` 없음 | 그중 잘림 |
|---|---:|---:|---:|---:|
| GSM8K | 1 | 1 | 696 | 278 |
| MATH | 35 | 31 | 1,548 | 1,404 |
| OMNI_MATH | 100 | 87 | 1,408 | 1,349 |
| MMMLU | 3 | 2 | 194 | 191 |
| KSM | 88 | 87 | 1,163 | 1,120 |
| 합계 | 227 (2.8%) | 208 | 5,009 (62.5%) | 4,342 |

2,048토큰 제한에 걸린 문항은 전체에서 Qwen2.5-72B 214개, Llama-3.1-8B 4,466개다. Llama-3.1-8B는 같은 문장을 반복하다 잘린 답이 대부분이다.

대체 규칙이 정답 처리한 답의 수다.

| 경우 | Qwen2.5-72B | Llama-3.1-8B |
|---|---:|---:|
| 스스로 끝낸 답 | 19개 중 0개 | 667개 중 312개 (lm-eval은 14개) |
| 2,048토큰에서 잘린 답 | 208개 중 5개 | 4,342개 중 139개 (lm-eval은 39개) |

- Llama-3.1-8B의 스스로 끝낸 답 312개 중 45개를 읽었다. 모두 "최종 답은 7입니다"처럼 모델이 말한 답을 집었다. lm-eval은 숫자 바로 뒤에 한글이 붙으면 건너뛰어서(설계 5번) 이 답들을 거의 읽지 못한다.
- Llama-3.1-8B의 잘린 답 139개는 응답 끝 130자쯤을 읽고 나눴다. 정답을 내고 같은 문장을 반복한 답 39개, 우연히 맞은 숫자 88개, 계산하지 않은 식을 sympy가 계산한 답 9개, 판단하기 어려운 답 3개다.
- Qwen2.5-72B의 5개는 모두 우연히 맞은 숫자다.

대체 규칙 설정을 바꿔 같은 응답을 다시 채점했다(다섯 묶음 평균).

| 설정 | Qwen2.5-72B | Llama-3.1-8B |
|---|---:|---:|
| 현재 방식 | 62.00 | 21.47 |
| `\boxed{}`만 인정 | 61.95 | 15.23 |
| "답", "정답", "답변", "결과" 뒤 숫자만 인정 | 61.95 | 17.88 |
| lm-eval | 60.33 | 15.76 |

- `\boxed{}`만 인정하면 우연히 맞은 숫자는 사라지지만, 맞게 푼 312개가 오답이 되고 Llama-3.1-8B의 GSM8K가 47.76에서 26.99로 떨어진다.
- "답" 같은 낱말 뒤의 숫자만 인정하면 잘린 답의 정답 처리가 139개에서 4개로 줄지만, 숫자만 쓰고 끝낸 정답 120개를 잃는다. `Language.KOREAN`의 번역 문구도 채워야 해서 이번 범위를 넘는다.
- 두 설정 모두 잃는 정답이 더 많아서 현재 방식을 유지했다. 우연히 맞은 숫자는 업스트림 PR의 Known issues에 적었다.

## 5. 합격 기준 점검

| 설계 6번의 기준 | 결과 |
|---|---|
| 프롬프트 차이 0건 | 충족. 8,011문항 모두 같다. |
| 생성 결과가 다른 문항은 원인을 설명한다 | 해당 없음. 생성을 한 번만 했다. |
| 점수가 다른 문항은 원인으로 모두 설명한다 | Qwen2.5-72B는 138개를 문항별로 설명했다. Llama-3.1-8B는 23개를 문항별로, 432개를 `\boxed{}` 없는 답으로 묶어 설명했다. |

설계 5번 표에 없던 원인이 두 가지 나왔다. 퍼센트 답(`\boxed{70\%}`)과, 잘린 답에서 우연히 맞은 숫자다. 둘 다 업스트림 PR의 Known issues에 적었다.

## 6. 끝까지 실행

Lighteval 명령으로 태스크가 도는지는 따로 확인했다.

- 업스트림 PR 브랜치 `team-b/hrm8k-upstream`(`69f06c6`), `SmolLM2-135M-Instruct`, 태스크마다 2문항, `--save-details`
- 다섯 태스크와 `hrm8k:_average`가 끝까지 돌았다.
- 저장된 문항별 점수가 지표를 직접 부른 점수와 10문항 모두 같았다.
- `make quality`와 테스트 35개(`test_hrm8k.py` 27개, `test_registry.py` 8개)가 통과했다.

## 7. 한계

- 생성을 Lighteval로 하지 않았다. Lighteval의 생성 경로는 6번의 10문항 실행으로만 확인했다.
- API 응답은 다시 요청하면 달라진다. 같은 숫자를 다시 내려면 근거 자료에 저장한 응답을 써야 한다.
- Llama-3.1-8B의 `\boxed{}` 없는 답 432개는 문항별로 어느 채점기의 채점이 옳은지 판정하지 않았다. 스스로 끝낸 답은 45개만, 잘린 답은 정답 처리된 139개의 끝부분만 읽었다.
- 데이터에서 새로 찾은 문제가 있다. MATH 155, 581, 1357, 1474, 1541, 2795번과 OMNI_MATH 155번 행은 `question`에 수식이 빠져 있다. `question-initial`에는 수식이 있다. 질문이 유난히 짧은 행만 찾아본 결과다. 나머지 행은 확인하지 않았다.
